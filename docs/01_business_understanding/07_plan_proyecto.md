
# ProyectoMercantil

## Fase 1. Comprensión del negocio

### Actividad 7. Plan inicial del proyecto

## 1. Propósito

Establecer una secuencia organizada de actividades
para desarrollar ProyectoMercantil bajo la metodología
CRISP-DM, identificando entregables y condiciones
de verificación.

## 2. Estrategia general

El proyecto se desarrollará mediante las seis fases
de CRISP-DM, de forma progresiva e iterativa.

Cada actividad deberá:

1. Tener un propósito definido.
2. Contar con instrucciones de ejecución.
3. Producir un resultado verificable.
4. Ser revisada antes de avanzar.

Si los resultados de una fase requieren modificar
decisiones anteriores, se documentarán los cambios.

## 3. Plan de ejecución

| Fase | Actividades principales | Entregable |
|---|---|---|
| 1. Comprensión del negocio | Problema, objetivos, preguntas, alcance, criterios, recursos y planificación | Documentación inicial |
| 2. Comprensión de los datos | Identificación de fuentes, metadatos, muestras, exploración y calidad inicial | Inventario y diagnóstico de datos |
| 3. Preparación de los datos | Ingesta, limpieza, transformación, integración y validación | Conjuntos de datos preparados |
| 4. Modelado y análisis | Indicadores, consultas analíticas, comparaciones y visualizaciones | Resultados analíticos |
| 5. Evaluación | Revisión de resultados, preguntas y criterios de éxito | Evaluación documentada |
| 6. Despliegue | Informe final, dashboard y documentación de uso | Resultados comunicados |

## 4. Prioridades de la fase 2

La siguiente fase se desarrollará en este orden:

1. Identificar y verificar las cuatro fuentes.
2. Examinar sus metadatos y variables.
3. Determinar su cobertura territorial y temporal.
4. Obtener muestras representativas para exploración.
5. Evaluar la calidad inicial de los registros.
6. Revisar la viabilidad de las preguntas de investigación.

El periodo definitivo de análisis se establecerá
después de verificar la cobertura de las fuentes.

## 5. Condiciones para avanzar

Una actividad se considerará completada cuando:

- Se haya producido el entregable previsto.
- Su contenido o funcionamiento se haya verificado.
- Las limitaciones relevantes estén documentadas.
- No existan problemas críticos sin resolver
  que impidan continuar.

No será necesario resolver todas las limitaciones
antes de avanzar, pero sí comprender su impacto.

## 7. Gestión de cambios

Los cambios relevantes en objetivos, alcance,
fuentes o metodología deberán documentarse.

Git se utilizará para conservar el historial
del código y la documentación.

## 8. Consideraciones

- El proyecto tendrá alcance nacional, con
  comparaciones principalmente departamentales.
- Se priorizarán los dos años completos más recientes,
  sujetos a disponibilidad y comparabilidad.
- Las preguntas principales serán P1 a P8.
- Las preguntas P9 y P10 serán complementarias.
- No se realizarán afirmaciones causales sin
  evidencia metodológica suficiente.
- La planificación podrá ajustarse según los
  resultados obtenidos.
